feat: read the lockfile, add --strict-undetermined, stop reporting unproven scans as clean

Review follow-ups, built rather than filed.

Lockfile resolution. Installed resolution cannot answer the case CI hits
most: a bare git clone, or the guard running before npm ci. The answer is
already committed, so read it. package-lock.json / npm-shrinkwrap.json
(v1's "npm:typescript@7.0.2" alias form and v2/v3's name + resolved
fields), pnpm-lock.yaml (importer entry, else an unambiguous packages
key) and yarn.lock (classic and berry, multi-spec headers, patch entries
deduped). Alias-aware throughout, so the TS6 shim locked under the
typescript key still never reads as the compiler. A lockfile beats an
override pin because it records a resolution that already happened while
a pin only says what a future install would do, so precedence is now
installed, lockfile, override, declared. Malformed lockfiles and trees
carrying two different typescript versions fall through instead of
guessing. Still fully offline.

--strict-undetermined (CLI flag and Action input) treats an unprovable
version as TypeScript 7, so a scan that cannot prove safety fails instead
of passing. Off by default, symmetrical with --strict-peers.

status no longer reports "clean" for a scan that proved nothing. An
undetermined version now yields status "undetermined", and the human
report says "found in what could be checked". A CI job gating on the
field could previously read a green light off a scan that resolved
nothing.

A workspace package declaring no typescript now inherits the repo root's
declared spec, the same way it already inherited the root's hoisted
install. Two packages in one tree could disagree before.

Action gains ts-version, ts-source and undetermined-count outputs so a
later step can branch on what actually resolved rather than on a boolean;
the recursive summary counts undetermined packages.

Verified end to end: the worked-example repo with node_modules deleted
now reports "TypeScript 7.0.2 detected (locked in package-lock.json)" and
exits 1, where the previous build said undetermined and exited 0. Corpus
re-measured after the change: still zero verdict flips across the 15
pinned repos. Clone check on the new resolver against the function it
parallels: 0.26 line similarity, well under the extract-the-mechanism
bar, and the shared lines are loop and try/catch scaffolding only.
